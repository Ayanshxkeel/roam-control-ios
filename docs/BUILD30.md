# Build 30: destination check-in before starting a spoof

Starting or moving a fixed-location spoof, starting a walking/cycling/driving route, retracing a route, and holding an interrupted route’s last point now require a destination check-in. The form asks users to tell a trusted adult and a friend their actual destination. It explicitly discloses that the entered text is sent to the Roam Control owner and stored in their private account report history, separate from Community map pins. Cancellation does not start a new spoof. Reports require an internet connection before device setup or airplane-mode handoff. Already-running route updates and pause/resume do not create repeated prompts.

The policy warning states that false information may lead to account removal and loss of spoofing access. The app cannot verify the truth of a destination, notify trusted contacts automatically, provide an emergency response, or remotely stop an offline device. Account deletion still revokes online access when checked by the client.

The authenticated safety-submit endpoint stores 3–1,000 characters and a session-derived user ID; caller-supplied account IDs cannot select another user. A unique request ID makes retries idempotent. The owner's existing inbox polls for new reports and uses the swipe-dismiss alert and numbered unread badge. These are in-app alerts, not APNs or lock-screen pushes. The owner must open/reopen the app with an internet connection. Owner dashboard user profiles and report inbox entries open a private, paginated destination history. Other users and the public Community endpoint cannot access those reports. Deleting a user cascades their reports. Owner submissions use a null account ID and show as Owner.

Validation: Release iPhone compilation, saved/offline login and inbox regression checks, and PostgreSQL service tests passed. Service tests cover validation, idempotency, owner-only report access, user-profile retrieval and deletion. Live service verification uses only a disposable QA user and synthetic destination, removed after testing. Popup presentation and device spoofing still need hands-on iPhone verification.
