# Build 29: delivered messages, alerts and numbered unread badge

The previous dashboard automatically marked messages read when the profile appeared or when its message list changed, including while the actual inbox wasn't being viewed. Build 29 removes those handlers. Only the separate Inbox marks its messages read. Swiping/dismissing the summary alert does not mark anything read; the red profile badge displays the unread count. The dashboard includes a matching numbered Inbox entry.

Messages use a dedicated authenticated, recipient-scoped inbox endpoint. The client loads every 100-message page, de-duplicates IDs and polls independently every ten seconds while active. Inbox requests have their own rate-limit bucket so map/presence polling cannot exhaust their session budget. Status/profile refresh no longer replaces the inbox with its old 50-message slice. The latest 50 messages are cached for offline display; full counts/history load when online. Read state is per account on this device, not cross-device synchronized.

The summary banner appears on the main app after the launch reminder, and on the profile/dashboard. It follows an upward swipe and can also be closed by X. Dismissing hides the alerts already fetched while preserving their unread badge. A new arrival can show another alert; each message uses a separate view identity to reset the exit animation. Open inbox reads the messages and clears their count. Alerts may be covered by other modal screens until those close. No background/lock-screen/APNs delivery is claimed: users need internet and the app open/reopened to fetch new messages.
